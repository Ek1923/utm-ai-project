# Project NEXUS (`utm_AI_Project`) — setup

A local multi-agent stack: a Fastify/TypeScript server, a React + three.js UI, and eight
agent personas that all run on **Ollama** against a single base model. Nothing leaves the
machine.

**This repository is source only** — no `node_modules`, no Python virtualenv, no model
weights. `setup.bat` restores all of it. See [What is not here](#what-is-not-here).

---

## 1. Prerequisites

| | why |
|---|---|
| **Node.js ≥ 20** | the Dockerfile builds on `node:20-alpine` |
| **Ollama** | every agent is an Ollama model; the server talks to `OLLAMA_URL` |
| **Python 3** + pip *(only for LoRA training)* | `training/lora/requirements.txt` |
| **NVIDIA GPU** *(optional)* | `docker-compose.yml` has a commented-out GPU reservation for the Ollama container; needs the NVIDIA Container Toolkit |

## 2. Install

```bat
setup.bat
```

A thin wrapper around the project's own `nexus\scripts\setup.ps1`, which does five things:

1. `npm install` in `nexus/`
2. `npm install` in `nexus/client/`
3. `pip install -r training/lora/requirements.txt`
4. `ollama pull phi3.5`
5. `ollama create` for the eight agents from `nexus/ollama/modelfiles/`

> `setup.ps1` pip-installs into whichever Python is on your PATH. If you want that
> isolated, make and activate a venv before running `setup.bat`.

## 3. The model

**One base model: `phi3.5` via Ollama** — the project's `download_phi.ps1` states ~2.2 GB.
Every one of the eight Modelfiles in `nexus/ollama/modelfiles/` begins with `FROM phi3.5`;
the agents differ only in their system prompt and parameters, not in weights.

| Modelfile | Ollama name |
|---|---|
| `APEX1` | `apex1` |
| `APEX2` | `apex2` |
| `FORGE` | `forge` |
| `SPARK` | `spark` |
| `ATLAS` | `atlas` |
| `TACTIX` | `tactix` |
| `VEGA` | `vega` |
| `NEXUS_UI` | `nexusui` |

Re-create them any time after editing a Modelfile:

```powershell
.\nexus\scripts\create_models.ps1   # needs `ollama serve` running
ollama list                          # check what landed
```

`nexus/ollama/built/` holds seven Modelfiles as they were last built — a snapshot, not an
input to setup. `SPARK` is in `modelfiles/` but not in `built/`.

### For LoRA fine-tuning instead of prompt-only agents

`training/lora/` is the QLoRA pipeline (`train.py`, `export.py`, `convert_hf_to_gguf.py`,
`pipeline.py`). Its `requirements.txt` says it plainly: install CUDA PyTorch **first**,
then the rest.

```bat
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install -r training\lora\requirements.txt
```

`nexus/training/` is a second, separate set of scripts for the FORGE agent
(`forge_train.py`, `forge_scraper.py`, `forge_merge_convert.py`) with its own
`requirements.txt`.

## 4. Run

```bat
ollama serve
cd nexus && npm run dev:server     REM http://127.0.0.1:3001
cd nexus && npm run dev:client     REM http://localhost:5173
```

Or the whole stack in containers — server plus an Ollama service:

```bat
cd nexus && docker compose up
```

### Configuration — `nexus/.env`

Three keys, no secrets: `PORT=3001`, `OLLAMA_URL=http://localhost:11434`, `NODE_ENV`.
It is committed deliberately, because the project does not start without it and there is
nothing in it to leak. **Do not put an API key or token in this file** — it is tracked by
git and this repository is public.

### Hard-coded absolute paths

Three source files carry paths from the machine they were written on, and they will not
exist on yours. Left exactly as they are, because this repository is a verbatim copy — but
you need to know before you run the training pipeline:

| file | what to override |
|---|---|
| `training/lora/export.py` | `CONVERT_SCRIPT`, `CAMELLLO_MODELS` — edit the constants |
| `nexus/training/forge_merge_convert.py` | `CAMELLLO_DIR` — already reads the `CAMELLLO_DIR` env var first, so set that instead of editing |
| `training/lora/gguf/*/Modelfile` | the `FROM` line points at an absolute merged-model directory |

> **Known quirk, left as it is:** `nexus/package.json` has
> `"train": "python training/train_agent.py"`, and no `train_agent.py` exists — the real
> entry points are the scripts named in §3. Not fixed here because this repository is a
> verbatim copy of the project.

### Why the runtime state directories are excluded

The server saves user-entered credentials into those files. In the source tree they held a
**live GitHub personal access token** (`nexus/server/data/system-config.json`) and a
**Wolfram Alpha API key** (`nexus/server/data/integrations.json`). Neither was ever
committed or pushed. They are gitignored so that no future run can push them either; the
server recreates both files empty, and the keys are entered in the UI.

Total in the source tree: **≈38 GB**, of which this repository is **3.5 MB in 335 files**.

No existing file was modified. `SETUP.md`, `setup.bat` and `.gitignore` are the only files
added.
